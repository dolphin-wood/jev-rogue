# 向 Jev 提问学到的事

[English](jev-findings.md) · **简体中文** · [日本語](jev-findings.ja.md)

这里记录用真实 Jev（TypeSafe 的 `choice` 模型）调校 Director 时得到的发现，好让下一个问题在写的时候就知道这些。每条写明观察到了什么、证据是什么、我们现在怎么做。除非另有说明，数字都来自同一组 8 个种子、`average` 技能档下的 route review 和 `pnpm answer-stats` 运行。

引号里的 state、选项和 instruction 原文保留英文，因为那就是发给 Jev 的字面内容。

## Jev 怎么回答

Jev 读取一份 `state` 和一组彼此独立的问题，对每个问题返回其选项上的概率分布。它是一个**分类器**：对一个 state，它说出哪个选项合适。它不跨调用做计划，不记得之前的回答，不计数，不比较数字，也不串联推理；每个问题都单独回答。

## 发现

<a id="finding-0"></a>

### 0. 退出选项是说出“都不合适”的唯一途径
Jev 总是返回一个总和为 1 的完整分布，所以即使每个选项都不适合当前 state，也总有一个排在最前，抽样器就会按它行动。模型要说“这里没有合适的”，唯一办法是提供一个正好表达这个意思的选项。因此每个问题都带 `fallback`（"None of these fits; let the game decide."），这也是 Jev 文档对可能落在选项集之外的输入的建议。它胜出时，该问题记为 **declined（拒答）**，由规则表回答。
- 拒答是 Jev 的回答，不是故障：它在说 state 或选项没给它任何依据。第一间房的外观问题（选项只相对于上一间房来定义）全部被拒答，这直接指向了缺失的历史。
- 因此**每个问题的拒答率**是一个诊断指标：经常拒答的问题，其选项是 state 无法支撑的（例如 `stat_family` 在修好 spec 之前是 17%）。
- 普通选项上的高概率不能证明它合适：没有退出选项时，错得最少的答案看起来也很自信。退出选项上的概率质量，应读作模型有多信任这张列表。
- 排序题不带退出选项（一扇门不能标成“都不合适”），代码也从不让它成为唯一的问题。
- **Confidence 取代不了它。** Jev 的 `confidence` 按分布的集中程度计算：平坦则低，单峰则高（它的文档建议把低于 0.3–0.5 的回答转给人）。它衡量的是“这些选项里选哪个”有多模糊，而不是“有没有一个合适”：所有选项都错时，错得最少的那个仍可能成峰并显得自信。我们在标签匹配式条款下正好见过这种情况（`stat_family` 的 confidence 为 0.54，而 17% 的提问落到了退出选项）。所以：退出选项回答“都不合适”；confidence 回答“选哪个、有多确定”。在游戏里，几个可接受选项之间的平坦回答不是需要转走的问题；从中抽样正是多样性的来源。只有在一次选错就会毁掉整局的决策上，confidence 下限才值得设。


### 1. 适合所有 state 的选项赢下所有 state
一个从不变化的 state 标签，会让所有以它为依据的选项处处都合适，问题就由条款最多的那个选项决定。`mana_sustain` 在 56 间房中有 50 间读作 `tight`（它是模拟施法循环得出的预测，不是实际游玩），于是 stat 门以 99% 赢下传送门问题。
**现在：**state 只放游玩中的实测值，分桶后给出，从不放预测或结论；一个不动的标签是要找出来的 bug。

### 2. 没有“不适用于”的选项就是吸收点
在 `what` / `not_for` / `examples` 形式的选项里，没有 `not_for` 的那个选项会吸走所有 state：`subspecies: none` 71%，`elite_presence` 81%，`mood_brightness` 在 `dim` 没有正面情形时 81% 是 bright。
给每个中间选项加上 `not_for` 后，`mood_particles` 从 96% 降到 55%。
**现在：**每个选项，无论手写还是生成，都带一条从它自身数据写出的 `not_for`；手写 spec 缺了它，测试就会失败。

<a id="finding-3"></a>

### 3. 示例在某些问题上是噪音，在另一些问题上是全部机制
从 `anchor` 删掉两个示例（其他不变），它就从 `tank` 56% 变成 `none` 99%；每个选项加回一个通用示例，又回到 86%。`stat_family` 也是如此。去掉示例反而*改善*了 density、waves、entry 和 zone 槽位。
**规则：**选项之间的区别在于它们*是什么*（一段描述）时，示例是噪音，会过拟合；选项之间的区别只在于*哪一行 state 成立*时，示例就是 Jev 学会这种对应的途径。只在后一种问题里保留少量通用示例（`briefing.test.ts` 固定了这份清单）。

### 4. 替某个选项论证的 instruction 会决定答案
instruction 在选项之前被读到。两句解释“升级会提高法力消耗”的话，就让 `stat_family` 在法力几乎不成问题的 state 上 95% 选 `mana`。一条写着 “`none` is a real answer” 的 zone instruction，就是在替 `none` 论证。
**现在：**instruction 公平地陈述原则；没有哪句话替某个选项说理。

<a id="finding-5"></a>

### 5. 要求多样性反而让答案更集中
Jev 看不到自己一直在给同一种门：每次调用都是一次全新的分类，而 “the affix badge has been on the last 4 offers” 对分类器来说只是 affix 选项又匹配上的一条事实。实测同类门最长连续次数：有代码上限时为 5，去掉上限为 7；去掉上限、同时在 state 里写出连续次数、给每种门加一条关于重复标记的 `not_for`、并在 brief 里写上多样性原则后，达到 **10**（affix 占比 48% → 60%）。
外观问题也一样：把规定性的那句 “the next room should not look the same” 换成单纯的事实后，它们的平均众数占比从 59% 升到 72%。
**规则：**多样性是*序列*的属性；分类器回答的是*state*。序列属性属于代码（抽样、软惩罚、上限），不属于措辞。`DOOR_STREAK_CAP` 保留。

<a id="finding-5a"></a>

### 5a. 围绕某个选项的强调式叙述会抬高它；中性计数不会
对照实验：固定一份 briefing（一个空键位、四个空的 affix 槽），使用 `portal_need` 问题及其真实 spec，只改变一句话，每种各做 15 次真实调用。`affix` 的平均概率：

| 加入的句子 | affix |
|---|---|
| 无 | 3% |
| "The player has said they want more affixes." | 78% |
| "The player has said they do not want any more affixes." | 0% |
| "The affix slots, affix tiers and affix cards of the build are the ones listed above."（重复这个词，没有新含义） | 4% |
| "Doors: the affix badge has been on each of the last 4 offers." | 7% |
| "…the affix badge has been on the last 4 offers, and the player walked past it every time." | 16% |
| "…over the last 4 rooms the player walked past the affix door each time it was offered." | 32% |
| "…over the last 4 rooms the player chose the spell or stat door every time, never the affix door." | 44% |
| "Spell doors and stat doors have hardly appeared lately." | 2%（spell 从 81% 升到 90%） |

所以这不是词频：重复这个词没有作用，而玩家明确表达的愿望或拒绝会被准确读取，否定也一样。但**描述玩家围绕某个选项的行为的历史会抬高那个选项**，句子越是围着它转，抬得越高，哪怕描述的行为是在回避它。Jev 把“玩家一直不选 affix”读成“这件事的重点是 affix”。“最近几乎没出现”也不会让它去补偿；它抬高的是被点名的那一种。
第二轮实验把*措辞*和*内容*分开。同样的历史写成中性计数，什么都不动：

| 加入的句子 | affix |
|---|---|
| 无 | 3% |
| "Doors taken in the last 4 rooms: spell 2, stat 2." | 3% |
| "Doors taken in the last 4 rooms: spell 2, stat 2, affix 0." | 7% |
| "Doors offered in the last 4 rooms: affix 4, spell 3, stat 3, gold 2. Doors taken: spell 2, stat 2." | 4% |
| 同样四间房，每间一行平实描述（"Room 3: offered affix, spell, stat; took spell."） | 3% |

所以抬高选项的是**强调式、叙事式的框架**（“every time”“never”“walked past it each time”），不是事实。中性计数是安全的，但它们也是惰性的：不会让 Jev 改变答案。
**规则：**历史写成平实计数和逐房间的平实行，不用强调词（“every”“never”“always”“room after room”“most/least”），也不写围绕某一个选项构造的句子。玩家真正表达过的愿望（他们自己的话）会被正确读取。多样性和回避属于代码（发现 5）。

### 6. state 里的算术不能让 Jev 从不排第一的选项动起来
在五次运行中，每次约 100 间房里，gold 都有 0 次是首要需求，无论 briefing 有没有写明这笔金币在下一个商人处能买到什么。它在门中 7% 的份额，完全来自代码用最久没出现的种类补齐较短的排序。
**规则：**如果某个选项必须以一定频率出现，那是代码里的下限，不是一条事实。

### 7. Jev 不会计数，所以计数要以一行给出
连续次数、“上次放松以来的战斗数”、“最近 3 张牌中有 3 张偏离风格”，都由代码算好，每项写成一行。一张需要 Jev 逐项数过去的列表，不是它能用的事实。

### 8. 未测量不等于零
一局开始时，事实默认是“没有受伤、刚刚放松过”，这正好匹配 `peak` 的每一条条款：每局的第 1 间房都是 `peak`。
**现在：**未测量的事实会直说（“no room played yet”）；第 1–2 间房不能是 `peak`（代码边界）。

### 9. 测试夹具会渗进答案
`affix_intent` 100% 回答 `wider`，是因为测试框架把起始预设固定为 `spam`，也没有输入意图。改变预设和意图后，结果是 41 / 32 / 27。
**规则：**要在多样的输入上评判一个问题；退化的答案可能来自夹具，而不是模型。

### 10. 基于同一组事实的两个问题就是一个问题
symmetry 和三个 mood 问题都基于同一套生命 / 伤害 / 清房速度划分，结果被当成一个问题回答（91–100% 同一个答案）。
**现在：**每个外观问题有自己的交替事实，最多再加一条真正会变化的事实。

### 11. 结论藏在内容文本里
写给设计者看的物品描述（“at the lowest mana cost in the attack pool”“suits a spam build”）作为选项文本到达 Jev，就被读成了答案。**现在：**选项和 state 文本从参数或面向玩家的描述写出，不从设计笔记写出。

### 12. 散文式 state 改变的不只是答案，还有 confidence
在标签匹配式条款下，无论匹配是否有意义，Jev 都以高 confidence 回答（`stat_family` 在拒答 17% 的同时 confidence 为 0.54）。散文式 briefing 降低了平均 confidence（0.68 → 0.60），同时改善了整局结果（奖励匹配构筑需求 40% → 49%，法术等级提升 62% → 71%，`stat_family` 拒答 17% → 0%）。confidence 不是跨格式可比的质量分。

### 13. 一个温度服务不了排序
把第一扇门抽得尖锐、其余抽得宽松，需要两个温度（`PORTAL_NEED_TEMPERATURE`、`PORTAL_TAIL_TEMPERATURE`）；只用一个尖锐的值，每间房都是同样的三个标记。

### 14. 运维
- 上游确实会出现 `529`（过载）；evaluator 在房间的截止时间内退避重试，然后回退到规则分支。
- 带完整卡池的第一轮请求约 52 KB；客户端和代理的请求体上限都得调高。
- 对玩家原话做关键词解析会出错（“clear rooms fast” 被读成抱怨法力）；应当让 Jev 自己读这句话。

### 15. 每一个我们试图靠提问得到的序列属性，最后都写进了代码
一轮里出现三次，形状都一样：设计意图是关于*一局*的，问题是关于*一个 state* 的，而承载意图的措辞变成了替某个选项的论证。

| 一局中要变化的东西 | 用文字表达的方式 | 实测 | 现在 |
|---|---|---|---|
| 房间外观 | 外观问题 instruction 里的交替要求，外加一行 state 统计每个部分已经持续多久 | `mood_particles` `calm` 91%，`mood_temperature` 65%，`symmetry` 58% | 删掉连续次数那行，instruction 保留意图，抽样前对上一间房的答案施加 `LOOK_REPEAT_PENALTY`（0.33） |
| 房间是否有优先目标 | instruction **和** `none` 上都写着 “a run needs both, or the rooms that do have something to aim at stop reading as different” | `anchor` `none` 85%；两处都删掉这句后 87% | 对上一间房的 anchor 施加同样的 0.33 惩罚 |
| 奖励展示哪些卡 | 无；奖励只按 Jev 的契合度排序 | 一局只见到 20 个 affix 中的 8.4 个、25 个法术中的 9.0 个，前五名占 73–75% 的位置 | `CARD_REPEAT_PENALTY`（每展示过一次乘 0.45，下限 0.12），并且在池中还有未展示卡时，保证尾部有一张 |

外观和 anchor 是干净的例子：**删掉文字什么都没变**（`anchor` 85% → 87%），代码项一加就立刻起作用。规则就是发现 5，而忽视它要付两次代价：一次在答案上，一次在提问花掉的 token 上。

<a id="finding-16"></a>

### 16. 中性化 state 改变了它并未针对的问题
把发现 5a 的规则（平实计数、不用强调词、不写围绕某一选项的句子）用到整份 briefing 上，改变的答案远不止门。8 个种子，`average`，briefing 分支，改动前后：

| 问题 | 改动前 | 改动后 |
|---|---|---|
| `mood_particles`（原始答案，代码惩罚之前） | `calm` 91% | `calm` 72% |
| `mood_temperature` | `cold` 54% | `warm` 54%（两者差距缩小到 16 个百分点以内） |
| `elite_portal` | `none` 58% | `none` 86% |
| `stat_family` | `survival` 75% | `survival` 42%，`movement` 39% |
| `subspecies` 拒答 | 15% | 9% |

外观问题没被动过就松开了：它们那行连续次数，正是围绕它们自己答案的句子。`elite_portal` 反向移动了将近三十个百分点，而这次改动完全没有针对它。所以改 state 就是改请求里的*每一个*问题；只测量本想修的那个问题，就会漏掉被改坏的那个。

### 17. gold 需要下限，而不是论证；商人需要上限
无论 state 有没有写明钱袋、商人的价格以及两者合起来能买什么，`portal_need` 都**在 101 间房中 0 次**把 `gold` 排第一。它在门中的份额完全来自排序的尾部。`GOLD_FLOOR_ROOMS`（gold 连续五次奖励没出现时就加进列表）把它从传送门的 7% 带到 8%，这是下限在起作用，不是说服。

商人正好相反：占传送门的 10%，gold 是 7%；在第 2–12 间房里，上限为两间房、四次提供，平均每局 1.5 间中途商人房。游玩反馈是“游戏在逼你花钱”。改为一间房、两次提供、第 4–10 间房的窗口后，商人降到 3%，gold 为 8%。

### 18. 对整个池都成立的否定是拒答，而不是过滤
变体排序的 `not_for` 开头是 “a room the player meets no ordinary <base> in”，这对几乎每间房的几乎每个选项都成立，因为敌人编成要在下一轮才决定。当*每个*选项都不适合 state 时，就没有合适的，退出选项拿走答案：排序在 15% 的房间里拒答，退出选项上 0.21。把 base 挪进 `what`，只根据标签写否定（标签在选项之间不同），拒答降到 9%。
这是发现 2 的反面，规则相同：基于整个池写的句子，无论指向哪边，都区分不了任何东西。

### 19. 只点名一个选项的边界挡不住两个选项一起的连续
`DOOR_STREAK_CAP` 会扣下“在最近四次奖励中每次都出现的那种门”，而 `doorStreakSpent` 按固定顺序只返回**第一个**这样的种类。三扇门从四种里抽，大多数奖励里都有两种相同的，所以两种常常一起连续：一次真实运行在第 1 到第 4 间房都提供了 spell *和* affix，上限扣下了 spell，affix 则延续到第五次，而名义上限是四。8 个种子、`average` 下实测：上限“开启”时同类门最长连续为 5。
**现在：**`doorStreaksSpent` 返回所有触发上限的种类，全部移出列表，下限是保留两种奖励类型。
**规则：**针对一组选项写的边界，必须在整组上判断，而不是只看其中第一个。一个上限实测等于它自己的限值加 1，这不是调参问题，是 bug。

### 19a. 上限仍然需要：没有它就连续十次
发现 5 是在请求里还带着那些文字时测的连续次数。在文字**全部去掉**后重新测量：中性 briefing，没有连续计数，任何选项上都没有关于重复标记的内容，`DIRECTOR_BRIEF` 里也没有多样性段落。8 个种子、16 间房的运行、120 次奖励：

| 标记 | 关闭上限时最长连续奖励次数 |
|---|---|
| affix | 10 |
| spell | 7 |
| stat | 6 |
| gold | 2 |

所以删掉那些句子，只是让它们不再*抬高*选项（发现 5a），对它们本想追求的多样性毫无帮助。原因在同一份日志里就看得到：`portal_need` 对 `build_shape` 读得很尖锐（raw 88% spell，forming 54% affix，formed 43% stat），而一局 16 间房里有 10 间处在 `forming`。每个答案对它自己的 state 都是对的；它们连成的序列就是同一个标记。**`DOOR_STREAK_CAP` 保留**，请求里也没有任何替多样性论证的内容。

### 20. 吸收点是理由最长、否定最窄的选项
这是发现 1 和 2 反复出现的形式。8 个种子、105 间房里，有四个问题在提问之前就几乎定了：

| 问题 | 众数答案 | 它的 `what` | 它的 `not_for` |
|---|---|---|---|
| `elite_presence` | `none` 83%（改后 76%，拆分外观后 72%） | 3 条替自己说理的条款 | 1 条窄条款 |
| `subspecies_weight` | `none` 70% | 3 条 | 1 条 |
| `size` | `standard` 88%（`compact` 0%） | 1 条 | 写的是商人房 |
| `next_tension` | `build` 85%（`release` 1%） | “the pitch most rooms sit at” | 2 条 |

每个问题的众数选项的 `what` 最后都在替自己论证：`none` “is the only room where what the player has learnt this run is simply true”，`build` 是 “the pitch most rooms sit at”。这是发现 4 的错误往左挪了一个字段，从 instruction 挪到了选项上。而且每个问题的相邻选项都背着含糊其辞：`elite_presence: one` 的否定有三条，`none` 只有一条。
**规则：**一个问题的各个选项之间，`what` 和 `not_for` 长度大致相同，也都不说哪个选项更常见。否定要从这个选项的代价写，而不是从它从未被选中的那些房间写。

### 21. instruction 只能点名 state 里印出来的事实
`subspecies_weight` 的 instruction 要求它根据 “how far the run has come, **how many rooms have been plain already** and how the player's build is doing” 回答。briefing 从来没写过这个。一间房里有过的变体以各自的名字出现在敌人列表里，所以要照原样回答，就得认出十三个 id 再数房间，这两件事分类器都不做（发现 7）；结果它 70% 回答 `none`。
**现在：**代码来数，state 用和 pitch 已有的相同形式写出来：“Rooms whose bodies were all ordinary: 4 of the 6 fought” 和 “Fights since the last room with a variant body in it: 3”。
**规则：**instruction 点名一条事实，就是承诺 state 会*以一行*给出这条事实，而不是给出一个能推导出它的东西。

### 22. gold 不看钱袋，哪个方向都不看
在请求里去掉所有替 gold 的论证后重新测量发现 6 和发现 17：选项不再拿钱袋对比货架，术语表不再把钱袋称为 “the priciest thing the merchant sells with change”，state 只给一次算术而不是两次。8 个种子、104 次提问，gold 在 `portal_need` 概率质量中的份额：

| 手上的金币 | gold 的质量 |
|---|---|
| 25 以下 | 1.7% |
| 25–49 | 3.3% |
| 50–94 | 2.4% |
| 95 及以上 | 2.6% |

基本持平，仅有的一点变化方向还是反的。同一批调用对构筑读得很尖锐（raw 88% spell，forming 54% affix，formed 43% stat），所以排序本身在正常工作；gold 只是不构成“这个构筑现在需要什么”的答案。**`GOLD_FLOOR_ROOMS` 保留，它是让 gold 出现在门上的唯一原因。**加事实来推动它，现在已经试了三次。

### 23. 点错了数量的选项，读起来再顺也是错的
`density` 决定一间房在**整场战斗中**有多少敌人；同时站在场上的有多少，由跑图进度爬坡决定，任何答案都改不了它。两个极端选项说的却是后者：“few bodies on the floor at once: a breather”，“many bodies at once: the hardest crowd the run currently allows”。于是这个问题描述的是游戏不会生成的房间；在开头几间房里，十二个敌人每次来四个，它描述的正好是玩家遇到的反面。
**现在：**选项引用每轮的 `DENSITY_TARGETS`，instruction 说明一次这个数是总数而不是同屏人数，state 给出这间房的两个上限（“Bodies this room may hold over its whole fight: 12”，“Bodies that stand on the floor at once in this room: at most 4”）。8 个种子、103 间房实测，答案散开了：normal 75% → 58%，sparse 10% → 25%，dense 14% → 17%。第一次尝试在 `sparse` 自己的 `what` 里放了一句贬义（“the one answer that leaves the floor emptier than this room would allow”），把它压到 **1%**，还有十分之一的质量落到退出选项；去掉这句评语后的数字就是上面那些。

**还有一个 Director 修不了的对等问题。**目标数乘以房间的轮数（`targetCount`），再被爬坡的总数截断后，组装器在每个房间序号、每种 pitch 下，对 `normal` 和 `dense` 返回*相同的编成*，`sparse` 也只小一点：实测第 7 间房 `build` 时 sparse 为 12–13 个敌人，另外两个都是 12–16；第 14 间房 `peak` 时为 12–19 对 12–20 和 12–20。选项文字如实说明了要求的是什么；房间怎么处理它，是 `packages/core` 的事。
**规则：**选项引用数字，就从游戏实际运行的常量里引用，并说明那个常量是什么数量。

### 24. 卡住的问题可能自己松开
外观挤在一间房的逗号列表里时，`mood_brightness` 97% 是同一个答案；`dim` 没有正面情形时是 81%。现在再测（期间亮度相关内容没有任何改动，但 state 做了中性化（发现 16），外观也有了单独的行），97 次提问中是 `dim` 52% / `bright` 48%。它的退出质量为 0.09，是请求中所有问题里最高的，这也是诚实的读数：两个单薄的选项，state 确实分不出高下。
**规则：**卡住问题的清单会过期。先重新测量再修，否则一轮工作会耗在一个已经自己好了的问题上，漏掉那个坏掉的（发现 16，从另一头看）。

### 24a. 一行一条事实，示例就引用那一行
上一间房外观的四个部分原本挤在一个逗号列表里（“Last room's look: mirrored layout, warm light, dim, busy particles”），所以四个外观问题各读其中一个分句、忽略另外三个；而每个问题的示例为了成为 briefing 真正会印出的一行，不得不引用全部四项，其中三项是该问题并不决定的字段的具体值。拆成四行后，每个问题的示例就是它自己的答案所依据的那一行（“Last room's brightness: bright”）。

8 个种子、16 间房的运行，在**玩家实际走进的房间**上测量（原始答案不等于房间：两者之间有 `LOOK_REPEAT_PENALTY`）：

| 外观 | 最长连续相同房间，前 → 后 | 平均连续 |
|---|---|---|
| symmetry | 9 → 4 | 2.4 → 1.6 |
| temperature | 12 → 6 | 3.1 → 1.8 |
| brightness | 10 → 7 | 2.1 → 1.5 |
| particles | 16 → 8 | 5.1 → 2.1 |

众数占比几乎没动（56/54/60/60% → 58/56/55/58%），所以这不是答案改了主意，而是答案开始*追踪这条事实*，而不是忽略它。原始分布因此集中得很厉害：`symmetry` 99% 回答 asymmetric，因为惩罚已经让上一间房是 mirrored，而这个问题现在读到了这一点。这是交替型问题的正常形态，不是卡住。凡是由代码负责交替的东西，看序列，不要看占比。

### 25. briefing 印两遍的分桶边界会自相矛盾
state 对每个实测量同时给出数值和分桶，所以切错的地方一行就看得出：`hits_per_shot` 以 `v >= 1` 分档，一个每发都正好命中一个敌人的玩家读作 **“Bodies struck per shot fired: 1.0, reads as several”**。常量上的注释说这个切分本意是“高于它说明法术在穿透或分裂”，所以标签偏了一档，而追踪 affix 的路线和奖励的 `eases` 事实正是从这个标签读的。（`packages/core/src/run/observed.ts` 中的 `hitsPerShotSeveral`；这里没有修，属于 core。）
**规则：**在分桶旁印出数值值得花这些 token，那是切错的分桶唯一会暴露自己的地方。

### 26. 对等规则不是定律，有两个问题因它变差了
发现 20 的修法（把众数选项的理由削到一条，把相邻选项的含糊也削到同等长度）一次用在了四个问题上，每一步都在同样八个种子、同样档位上测量。两个朝对的方向移动，两个朝错的方向走得更远：

| 问题 | 之前 | 对等之后 | 第二轮之后 |
|---|---|---|---|
| `elite_presence` `none` | 83% | 76% | — |
| `density` `normal`（计数已修正，发现 23） | 75% | 64% | 57%，`sparse` 10% → 24% |
| `size` `standard` | 88%，`vast` 18% | **100%**，`vast` 0% | — |
| `subspecies_weight` `none` | 66% | **90%** | **100%** |

`size` 和 `subspecies_weight` 已回退到测得更好的文本。可以得出两点。第一，选项的长度是一个权重，而不是一根杠杆：缩短众数选项的理由是去掉一条论证，而在 state 没有给这个问题其他依据的地方，剩下的就是一个要读的内容更少的安全答案。第二是 `subspecies_weight` 的第二轮：state 加上了它自己的 instruction 要求的那条事实，“how many of the fights so far held a variant body”，而每种写法（先是单边的，然后是双边计数）都把答案进一步推向 `none`，因为在一局没有变体的运行里，这条事实只能说*这局一直很普通*。一个永远只关于一个选项的计数，就是在替它论证，无论是否写成双边计数。

这两个问题现在都卡在一个答案上或附近，已经没有什么话可以对它们说了。下一步要试的不是更好的句子，而是发现 6 和 17 对 gold 得出的频率下限：N 间房没有变体后，`none` 离开选项列表；`size` 要么同样处理，要么干脆去掉这个问题。**两者都没实现**；它们是交给硬规则审查的提案，因为边界是用户的决定，不是某一轮工作的决定。

### 27. Jev 从不做出的选择是一个频率，而频率归代码管
硬规则审查后，有三个问题无论 state 说什么都停在同一个答案上。`subspecies_weight` 100% 回答 `none`，`size` 在发现 26 的改写后 100% 回答 `standard`。`next_tension` 只有 1% 回答 `release`，即使连续十三场战斗没有喘息、只剩一颗心，也是 0%。所有由文字构成的杠杆都试过了：中性文本、长度对等、instruction 要求的事实、删掉自我论证的条款。没有一个让答案朝稀有选项移动，好几个还让它离得更远。

**已决定（用户，2026-09-25）：**稀有答案采用**规则下限**，和 gold 一样（发现 17）。N 间房没有变体后，`none` 离开 `subspecies_weight` 的列表。N 间房没有放松后，下一个 pitch 可以是 `release`。`size` 同样处理：N 间房都是 `standard` 后，它离开列表。剩下的仍由 Jev 排序，所以在窗口内选哪个变体、哪个尺寸、什么时候，仍由 Director 对 state 的判读决定。代码只决定稀有选项终究会发生。

**规则：**当一个问题的稀有选项对游戏重要，但没有任何 state 能让 Jev 选它时，这是一个**序列属性**：某件事在一局中多久发生一次，而不是什么适合当前 state。把它写成代码里的下限，而不是在选项文本里替它论证。症状是：在专门设计来偏向它的各种 state 下，稀有选项始终在 0% 左右。加下限之前先看发现 24：重新测量，因为卡住的问题可能自己松开。

### 只相对于过去来定义的选项，在第一次提问时无从匹配
四个外观问题的选项都是围绕上一间房写的（“…whose last floor was already mirrored”）。第 1 间房没有上一间房，真实 Jev 在一次真实会话的第一间房里把四个问题全部拒答。
**现在：**第一间房的外观不提问；由规则表填写，决策标为 `no_history`，而不是拒答。**规则：**选项只有相对历史才有意义的问题，在有历史之前不提问。

### 28. 中性卡牌文本没有改变 Jev 的任何回答；风格倾向来自 Jev 本身（2026-09-25）
法术重做之后（doc 006，三十九个法术），每张卡的 `what` 都改写成中性事实，也就是内容表里的 `description`，选项现在用它代替 `PLAYER_TEXT`；lane、family 和 school 的 spec 也去掉了结论（“widens nothing”、“buys the run room to go wrong”、“a bar that buys few casts ... is about to stop working”）。

**措辞本身是惰性的。**对照实验：从下面这次运行中取 30 个第一轮请求（每种风格 4 次法术奖励和 2 次 affix 奖励），每个请求发两次，state、instruction 和每条 `not_for` 完全相同，只改变卡牌的 `what`：中性描述（A）对比旧的 `${name}: ${PLAYER_TEXT}`，后者带有 “best when enemies bunch up”、“the hardest-hitting common attack”、“your answer to being surrounded”（B）：

| 问题 | n | 首选卡相同 | 贴合风格的质量 A / B | 平均总变差 |
|---|---|---|---|---|
| spell `overall` | 20 | 100% | 0.94 / 0.92 | 0.10 |
| spell `for_style` | 20 | 75% | 0.97 / 0.97 | 0.15 |
| spell `for_needs` | 20 | 65% | 0.41 / 0.40 | 0.19 |
| affix `overall` | 10 | 100% | 0.69 / 0.70 | 0.13 |
| affix `for_style` | 10 | 100% | 0.80 / 0.84 | 0.12 |
| affix `for_needs` | 10 | 60% | 0.27 / 0.30 | 0.22 |

同一批请求里的其他问题，变化最多也就是一次抽样的量（`next_tension`、`size`、`portal_need`、`mood_temperature`、`affix_intent` 首选答案 100% 相同；`variety` 90%；`space` 83%）。所以那些结论并没有在引导卡牌问题：奖励读的是构筑和所选风格，卡牌文本用来区分候选，而不是给它们排序。这正是中性事实规则想要的结果：文本可以写得像规则表一样平实，Director 不会因此失去什么。

**风格倾向是真实的，而且来自 Director。**10 个种子，`expert`，briefing 分支（每种风格两局，`route-review` 的玩家），与同种子的规则分支对比；奖励界面上贴合风格的卡牌占比，括号内是池中基础比例：

| 风格 | 法术，Jev | 法术，规则 | affix，Jev | affix，规则 | 拿走的卡中贴合风格的，Jev / 规则 |
|---|---|---|---|---|---|
| spam (21%) | 47 张中 64% | 35 张中 43% | 26 张中 38% | 47 张中 19% | 71% / 45% |
| nuke (26%) | 24 张中 46% | 31 张中 35% | 9 张中 33% | 28 张中 29% | 31% / 30% |
| area (28%) | 38 张中 58% | 35 张中 54% | 44 张中 27% | 44 张中 25% | 61% / 54% |
| dot (26%) | 29 张中 48% | 38 张中 42% | 38 张中 29% | 38 张中 29% | 59% / 46% |
| melee (26%) | 35 张中 66% | 38 张中 50% | 35 张中 40% | 41 张中 37% | 85% / 66% |

- **Heavy 在两个分支上都是单薄的风格**：两局 Heavy 都早早死亡（两局共 24 张法术卡），它也是唯一一个在 Jev 下拿走的卡并不比规则表更贴合风格的风格。
- **area 和 dot 的 affix 奖励几乎没有倾向**（两个分支都是 27–29%，基础比例 20%）：`for_style` 把 0.80 的质量放在贴合风格的卡上，但混合、万能位和新奇惩罚又把它摊开了。
- **Jev 从不被拿走的卡：**Mana Darts 被提供 13 次（6 次给 spam 局，也就是它所属的风格），被拿走两次，一次都不是 spam 局；Shatter 被提供 5 次，从未被拿走。**总被拿走的：**风格自己的起始法术作为升级（melee 局里 Spirit Blades 6 次中 6 次），spam 局里 Seeker Swarm 8 次中 6 次。
- **Ward 大约出现在五分之二的 affix 界面上**（152 张 affix 卡中 20 张，被拿走 9 次）：它适合每种形态，而且只要生命低，它就是 `need` 卡。
- **Director 展示的池比规则表少**：每局 10.8 个不同法术和 10.2 个 affix，对比 13.7 和 14.8；最常见的五张占 66% 的位置，对比约 50%。同时 `variety` 在 84% 的奖励中回答 `low`，这让抽样更尖锐（在连续两次偏离风格时 14 次中有 9 次回答 `low`，只有完全没有偏离时才回答 `high`）。

同一份日志里塌缩的问题（n ≥ 50，原始答案）：`symmetry` asymmetric 96%，`mood_temperature` warm 90%（两者都由 `LOOK_REPEAT_PENALTY` 交替：实际房间是 58% 和 56%），`next_tension` build 88%，`anchor` none 85%，`variety` low 84%；卡牌问题是分散的（`overall` 众数 11%，`for_style` 7%）。上面的 A/B 排除了卡牌文本是它们的原因。
**规则：**一句不决定答案的结论，也值得删掉：这里删掉它没有任何代价，而它是一句以后的某次修改可能会让它变得决定性的话。措辞改动要用已记录请求做 A/B 来测量（同一 state，只改一个字段），不要拿两次运行比，两次运行的编成和种子在其他一切方面都不同。

### 29. Heavy 的早死是操作手的问题，不是 Director 的；Jev 分支只有一个起始法术（2026-09-25）
第 28 条里两局 Heavy 的早死，被读成 Director 倾向单薄。在改动任何东西之前先测规则分支（`route-review` 的玩家，每种风格和档位 40 个种子），发现没有 Jev 时也有同样的早死（expert 下 Heavy 57% 的局到达 boss，其他风格 82–100%），并在两个分支共用的参考玩家身上找到了原因：

- **施法轮换按下第一个就绪的键**，而冷却短于自身前摇加后摇的键，每次手空下来时都是就绪的。一局 expert Heavy 施放了 Earth Spikes 214 次，另外两个键 11 次和 0 次；`average` 玩家（施法间隔 1.2 秒）在任何风格下都只按第一个键。重做之前那个键是 Magic Bolt，所以每种风格测出来都一样。轮换现在按键位轮流（最久没施放的就绪键优先）。
- **Earth Spikes 每次施放让施法者减速到一半**，持续 700 ms，而这是 Heavy 开局唯一的键：第 1 间房一个落单的射手要花 12.8 秒、掉 4.5 HP，只用剑则是 4.2 秒、不掉血。`move_scale` 0.5 → 0.85。
- Ember Dart 需要在一秒内命中第二次才能点燃，`average` 玩家从来打不到；`element_power` 1.6 → 2.4（仍然是两次命中）。

规则分支，expert，到达 boss 的局：Heavy 57% → 99%（80 个种子；重做前 92%）；`average` Heavy 20% → 62%。

**然后是 Jev 分支**，5 个种子，`expert`，briefing，每种风格一局（142 次调用，没有回退）：五局都到达了 boss，没有奖励被标记；Heavy 那局赢下了整局。三局死在 boss，而 boss 当时正在重做，不是本条的数字。它显示了两点：

- **只有一个起始法术时，Jev 在早期法术界面上把起始法术的升级排第一**（`overall` 上约 0.75），而参考玩家拿第一张卡：Barrage 局到第 3 间房都只有一个键，Blade 局到第 4 间房，而规则分支进入第 2 间房时平均有 1.9 个键。一个人会不会选升级而不是第二个键，是选择者的问题，不是 Jev 的；测试框架是故意拿第一张卡的。
- **Mana Darts 的否定写的正是它的最佳用法。**它写着 “a fight the key is pressed through without rest”，这正是 Barrage 的玩法，按 doc 006 也是这个键输出最高的方式。改成它真正的代价（“a bar running dry: each press costs a whole cast, however few darts are banked”），并在第 1–3 间房的 15 个已记录第一轮请求上做 A/B，state 相同，只改这句话：

| 问题 | Barrage 局 (n=3)，质量 新 / 旧 | 其他风格 (n=12)，新 / 旧 | Mana Darts 排第一，新 / 旧 |
|---|---|---|---|
| `overall` | 0.06 / 0.03 | 0.01 / 0.01 | 0 / 0 |
| `for_style` | 0.14 / 0.04 | 0.00 / 0.00 | 0 / 0 |
| `for_needs` | 0.24 / 0.31 | 0.14 / 0.20 | 15 次中 5 / 8 |

  对它所属风格，贴合风格的质量涨到三倍，需求质量下降了，因为新条款点名的是法力消耗。无论哪种写法，它都没在 `overall` 排第一：在这些房间里，起始法术的升级在 `overall` 上领先一个数量级。请求太少，不足以下结论；错的是文本，不是频率。

**规则：**在把某种风格的结果算到 Director 头上之前，先看操作手怎么用这些键：`pnpm play` 会打印每个持有法术每分钟的施放次数（`SPELL_USE`）。一个参考玩家从来不按的键，会把一个奖励问题变成一个看起来像奖励问题的测试框架 bug。

### 30. 方向印反的计数会被倒着读；剩下的又是操作手的问题（2026-09-25）

### 33. 按 confidence 读取 Jev 的回答，而不是透过温度（2026-09-25）
TypeSafe 的文档把 Choice 定义为它的 `choice`（概率最高的选项），并以 `confidence` 把关，后者由分布的离散程度计算（`(n × peak − 1) / (n − 1)`）：对有把握的回答照做，把低 confidence 当成模型在说它不知道。Director 原本对每个回答都按各问题的温度抽样，大多是 0.4（doc 002：argmax 从不决定玩法，否则一个 state 永远只生成一种房间）。低于 1 的温度会把 Jev 的第二选项读得比 Jev 说的更弱：在锚定原则下（发现 32），Jev 在上一个 school 上放了 0.46，而在 0.4 的温度下，它 78% 的时候作为重复回来。

离线，在四次真实运行记录下的回答上（60 间房，每种规则 2,000 次抽样；后面的回答是以真实发生的历史为条件的，所以这是一个方向，不是预测）：

| 规则 | 偏离 Jev 首选 | 与上次相同 | 最长连续 | 最常见答案占比 |
|---|---|---|---|---|
| 各问题温度（原上线版） | 18% | 60% | 5.1 | 71% |
| 始终用 `choice` | 0% | 68% | 6.0 | 77% |
| confidence ≥ 0.5 时用 `choice`，否则按原始分布 | 20% | 60% | 5.1 | 71% |

confidence 读法在整体上与温度相当，而不需要为每个问题设一个数值；而且正是在这里，原则带来的犹豫才会变成一个不同的答案：在重放的 `spell_school` 请求上，上一个 school 再次出现的比例，温度下为 65%，始终用 `choice` 为 82%，confidence 读法下为 31%。始终用 `choice` 会把 `symmetry` 锁死（100% 重复，平均连续 11.8）。

**现在：**Jev 回答的问题在 confidence ≥ 0.5 时（TypeSafe 建议的下限，`JEV_CONFIDENT`）采用 `choice`，低于它时从原始分布中抽样；confidence 是 TypeSafe 的统计量，计算在代码过滤选项和施加重复惩罚之后实际抽样用的分布上。规则分支和随机分支保留各自的温度，排序（`portal_need`、`subspecies`）和卡牌抽取也保留。代价：Jev 总是很有把握的问题现在就固定了：`size` 在 92% 的房间里是 `standard`，有一局的 stat 门连续十次都是 survival。

**规则：**按 TypeSafe 文档的方式读取 Jev 的回答。有把握时用它的 `choice`，没把握时用它的分布；温度是设计者对 Jev 不确定性的重新解读，而它恰好藏起了我们要求的那一点犹豫。

### 34. 与卡牌分开决定的承诺会重复；门在开启时连同背后的卡一起决定（2026-09-25）
法术门承诺一个 school（它自己的问题，在房间的第二轮提问），背后的奖励被强制包含一张该 school 的卡；stat 门承诺一个 family。即使有锚定原则和 confidence 读法，四次真实运行中仍有 68% 的法术门重复了上一扇法术门的 school。school 是一个代理：玩家想要的是自己风格的法术，而一种风格横跨多个 school（void 里既有 spam 法术也有 nuke 法术）。改成问前两三个 school 也无济于事：Jev 的排序很稳定，它的前两名在一局的每扇门上都是同一对（storm + void 10 次中 10 次，spirit + stone 7 次中 7 次）。

而且门是在房间开始时决定的，早于它们所依赖的战斗：有一局以 90 点生命中的 37 点走进第 5 间房，以 12 点走出，穿过的是为 37 点选的门（fountain 为 0.14），两间房后死亡。

**现在：**房间只决定它有几扇门。出口打开时（奖励被拿走、金币房的金币撒出、进入商人房），门以待定状态升起（旋转、看不清内容，旁边显示“正在开启…”），由一次请求决定：传送门问题，加上每种门可能对应的、背后房间将提供的卡，依据刚打完的战斗和刚改变的构筑来判断。每扇门保留自己种类的卡，门上的标记从这些卡读出；背后的房间正好提供这些卡，不再提问。`spell_school`、`stat_family`、它们的第二轮追问和 school 上限都已去掉。

四次真实运行（每种风格一次，`expert`），对比四次带 school 承诺的运行：

| | 承诺 school | 卡与门一起决定 |
|---|---|---|
| 符合所选风格的法术卡 | 69% | 67% |
| 展示的法术中不同法术占比 | 63% | 60% |
| 最常见 school 在法术卡中的占比 | 53%（带上限时 64%，2 局） | **46%** |
| 一局见到的 school 数（共 7 种） | 4.3（4.0） | **5.3** |
| 法术门标记与上一扇相同 | 68% | **41%** |
| 每局 Jev 请求数 | 29 | 40 |

风格贴合和卡牌多样性保持住了；school 的分布变宽了。代价是每间房多一次请求，而开门请求带着三个卡池（80–103 KB）：每局输入 token 约多 60%。这些运行里没有一次是在半血以下做出门的决策，所以 fountain 现在是否会在该出现时出现，还没有测量。

**规则：**与所描述内容分开决定的标签或承诺，只要 Jev 的偏好稳定就会重复，无论内容本身多么多样，然后就需要一条规则去压住它。先决定内容，再从内容读出标签。

### 35. 对整个池问 choice，问的是“哪一张才是答案”；应该逐张问（2026-09-27）
来自试玩的反馈：Jev 分支里有些法术和 affix 几乎从不出现。用 `pnpm card-exposure` 测量（十局，风格轮换，在每个请求的回答上重放 Director 自己的抽样）：39 个法术中有 17 个的曝光不到均匀抽样的四分之一，最冷的只有 0.01；前十张占了 72%。同种子的规则分支：没有一张低于四分之一，最冷 0.67。

原因不是风格倾向。每个法术都属于某个风格，而冷门卡**在自己的风格里、从第一次奖励起**就是冷的，那时玩家还什么都没选：spam 的第一个奖励界面上，Shock Arc（起始法术的副本）是均匀份额的 25.7 倍，Mana Darts 5.5 倍，同属 spam 的 Frost Needle 和 Spirit Ally 为 0。也不是强度：按 `spell-bench`，Doom Sigil 是第四强的法术，却只有 0.03；出现最多的是 Stone Ward（`for_needs` 轴对每种风格都推的防御卡，4.6 倍）和 Crescent Edge（池中最弱的法术）。也不是措辞：发现 28 已经证明卡牌文本是惰性的。也不是 variety：`variety` 回答 `high` 的次数多于 `low`，而温度 1.0 会原样保留分布。

**问题的形式不对。**`overall` 问的是“哪个法术最该出现”，而 choice 分布是每个选项*是那个答案*的概率。在三十九张卡里，一个风格中第二好的卡理所当然几乎从来不是最好的，所以从这个分布里抽样，就是只从赢家里抽。把问题问得更清楚不会改变这一点，把历史写进 state 只会更糟（发现 5）。

**现在：**Jev 分支上每张候选卡各是一个 Noul，`fit_<id>`：“把这张卡放在这个玩家的奖励界面上合适吗？”，附卡牌描述和它不适用于什么；brief 在 state 里只出现一次。奖励按每张卡的 yes 抽样，由 Jev 自己的 `variety` 回答决定取 4、3 或 2 次方（yes 是对单张卡的判断，原样抽样几乎没有倾向）。规则分支保留三个 choice 轴。在此之前，用十个已记录请求在同一批卡上对比了 Noul 和 Score：Noul 更能把本风格的卡与其余分开（AUC 0.93 对 0.89；choice 回答为 0.83），Score 只用到四档中的下半截，而且更贵。

十局，同样的种子，先 choice 后 Noul：

| | choice | Noul | 规则分支 |
|---|---|---|---|
| 低于均匀份额四分之一的法术 | 17 | **3** | 0 |
| 最冷的法术 | 0.01 | **0.09** | 0.67 |
| 前十张法术占的份额 | 72% | **47%** | 34% |
| 一种风格两局里出现过的本风格法术 | 49 中 28 | **49 中 42** | 49 中 40 |
| 每局不同法术 / 每局法术卡 | 10.8 / 18.0 | 11.3 / 16.3 | 16.2 / 22.9 |
| Stone Ward / Crescent Edge | 4.6× / 4.0× | 0.95× / 1.9× | 1.1× / 0.8× |
| 低于均匀四分之一的 affix | 2 | 0 | 0 |
| 每个奖励请求的输入 token | 25.9k | **21.8k** | — |

起始法术的副本在前期仍然领先，Meteor 在 nuke 局里仍然逐渐上升：对构筑的倾向保留了下来，而且仍由 Jev 决定。现在最冷的是 Frost Needle 和 Glacier Spike，0.09：Jev 在每种风格里都把冰系排在其余之后，这是一种判读，不是塌缩。affix 变化较小（它们本来就没有那么集中）；同一风格的两局仍然共享三分之二看到的 affix，这来自 affix 门的次数（每局 21 张 affix 卡，池中只有 19 个），而不是抽样。

**玩家的话必须写进判断标准。**最初的措辞是“值得一个位置：它适合这个构筑和这个玩家”，Noul 于是以构筑为主来读：在同样十个已记录的法术奖励上，只改玩家写的话，“只要火系法术”让火系在抽中位置里的比例从 11% 升到 18%，而且只有 dot 局上升；“I only want Frozen Orb”只让它在十次中的一次排第一（2% → 10%）。choice 问题原本做得更好（火系 17% → 40%；Frozen Orb 十次全部第一，44%）。把玩家的话写进 instruction 和 `true`（“玩家的话所要求的，或适合这个构筑的”）之后，同样的请求中火系为 55%，Frozen Orb 十次全部第一，36%；没写话的请求不受影响（火系 12%，本风格卡 78%，此前 76%）。

**判断方法在 state 里只写一次。**判断方法那一段在每张卡的 instruction 里都相同，约 500 字符，一个门请求里重复七十次；现在它作为 `card_judging` 在 state 里只出现一次，每个问题只保留自己的卡牌文本和判断标准。在上面同样十个奖励上，各卡的 yes 与逐卡措辞的相关性为 0.97–0.98（同措辞重跑一次为 0.99），对玩家的话的反应保持不变（火系 55%，Frozen Orb 十次全部第一），法术池请求的输入 token 从 14.7k 降到 10.7k。在此基础上跑十局：低于均匀四分之一的法术 4 个，前十张占 48%，一种风格两局里出现过的本风格法术 49 中 43，每局 18.4 张法术卡中不同的 12.6 张；每个奖励请求 19.3k 输入 token（choice 25.9k，最初的 Noul 措辞 21.8k），整局请求的 token 比 choice 分支少 16%。

**规则：**choice 问题用来挑一个。代码要从列表里抽几个时，就逐项提问，每项一个 Noul，由代码决定这些判断读得多尖锐；把 choice 分布当作抽样分布，就是只从赢家里抽。

### 36. 词条池比一局小；原因不在 Jev 的抽法（2026-09-29）
试玩反馈："打了几把来来回回都是那些词条，尤其是 Jev 模式"。用 `pnpm card-exposure`
测（每条臂五局，流派轮换）：Jev 臂一局见到 **16.8 张词条卡**，而构筑实际能被发到的词条池
平均只有 **12.9 个**（rule 臂一局 8.5 张）。一局就把能拿到的池子看完了，同流派的下一局看到的
还是同一个池子。抽法有加剧——harvest 占均匀份额的 2.1 倍，灌注类 Kindle、Rime 只有 0.26 倍和
0.29 倍——但任何抽法都不可能把十七张卡铺在十三个选项上而不重复。

池子还按形状严重偏斜：二十二个词条里有十四个挂在弹丸的命中、击杀、到期或撞墙上，所以弹丸
起手能被发到十八个，而 Earth Spikes 九个、Crescent Edge 十个、Counter Stance 六个。在强度 I
的门上，非弹丸法杖只能从六个"任意形状"词条里抽，其中三个是元素灌注。

**现在：** 新增六个词条，挂在所有形状都能触发、或弹丸键原本缺的时机上（`repulse`、
`aftershock`、`parting`、`whirl`、`spillover`、`drag`）。弹丸起手可被发到 23 个，Earth
Spikes 13 个，Crescent Edge 15 个。同种子，Jev 臂：

| | 之前 | 之后 |
|---|---|---|
| 构筑能被发到的词条，每次发牌平均 | 12.9 | **17.2** |
| 五局里上过屏幕的词条 | 19 / 22 | 23 / 28 |
| 最热词条相对均匀份额 | harvest 2.10× | harvest 1.93× |
| Kindle / Rime 相对均匀份额 | 0.26× / 0.29× | 0.82× / 0.73× |
| 池子前四分之一占曝光 | 55% | 45% |
| 一局词条卡数 / 不同词条数 | 16.8 / 11.8 | 16.8 / 11.8 |

跨局的发牌摊开了；**一局之内没有**：每十七张词条卡里仍有五张是本局已经出现过的，因为 Jev
评价高的卡在"是"被四次方放大之后，经过 `CARD_REPEAT_PENALTY` 仍保有大部分权重。这是序列属性，
属于代码（第 15 条），不该去问 Jev。

**然后是方向与形状**（同一天）：再加六个词条，让导演的每个方向在每种形状上都有卡，并把只有一张卡的施法频率方向换成「自动施放」；再加八个法术——四个只有一个法术的形状各添一个，外加叠加刀环、锚定刀环、抛射弹和引导光束。同五个种子：每次发牌可发的词条 21.5 个，一局 15.6 张词条卡里 12.2 个不同，最热的仍是 Harvest（1.93×）；48 个法术里 38 个上过屏幕，新法术在均匀份额的 0.56×–1.16× 之间，只有 Blizzard 是 0.20×——Jev 在每个流派都给冰系低分，与第 35 条里 Frost Needle、Glacier Spike 的情况一样。灌注类更低了（Kindle 0.18×）：新进池的生存和自动施放卡排在它们前面。一局之内的重复没有变化，原因如上，在抽法。

**然后是拒绝**（同一天）：同一套键位下被跳过两次的词条本局不再发（`exhaustedAffixes`），III 级门的新法术自带一个词条。同五个种子，Jev 臂：一局 12.6 张词条卡里 10.2 个不同（重复 19%，之前 22%），最常见的五个占一局词条卡的 41%，之前 59%。这次的局更短——Jev 调用 156 次对 199 次，一局法术卡 16.8 张对 19.2 张——所以张数不能直接比；前五占比是更稳的读数。

**规则：** 卡池的大小要按一局会看到的卡数来定，而且按构筑算、不按全表算；一局就能看完的池子，
无论导演怎么做都会重复。

## 由此得出的常规做法
- State：来自游玩的事实，用文字写，计数预先算好；不下结论，不做规定；每个自创术语都要解释。instruction 只能点名 state 以一行形式印出的事实。
- 选项：单个条目，每个都有 `what` / `not_for`（生成的也一样，从条目自己的表格行写出）；只在选项区别在于哪条事实成立时，才加少量通用示例。一个问题内各选项长度大致相等只是起点，不是定律：它让两个问题朝对的方向移动，两个朝错的方向（发现 26），所以要像其他改动一样测量。
- State：按实际生成的样子描述这一局（每间房、它的战斗、每扇门及其背后的内容），而不是 Director 自己的回答列表，Jev 会把那份列表读成要保持的先例（发现 31）。
- Instruction：公平地陈述原则。关于一局的原则，可以在 state 印出这一局后加入，前提是说明它在哪里，以及没有时它不起作用；先在没有历史的请求上测它（发现 32）。
- 代码：安全边界、Jev 不回应的序列属性（连续次数、频率下限）、算术。一个在任何 state 下 Jev 都不选的稀有选项，要给频率下限，而不是更多文字（发现 27）。
- 回答：confidence 至少 0.5 时用 Jev 的 `choice`，低于它时按原始分布，而不是用温度重新解读它的不确定性（发现 33）。
- 标签：先决定内容，再从内容读出标签；与所描述内容分开决定的承诺，会随着 Jev 稳定的偏好而重复（发现 34）。
- 内容文本：卡牌的 `what` 是它的中性描述，绝不是面向玩家的文案；结论即使不决定答案也要删，因为以后的修改可能让它变得决定性（发现 28）。要说明拿走一张卡会对法杖做什么（“a copy fills no key; keys 2 and 3 stay empty”），而不只说这张卡是什么（发现 30）。
- 计数：先印出条目本身，再给计数，方向与问题所问一致；方向印反的计数会被倒着读，而与相邻选项只差一行计数的选项，需要把那一行作为示例（发现 30）。
- 在怪 Director 之前，先检查操作手：参考玩家的施法轮换和选卡方式，决定了两条起初看起来是 Jev 问题的发现（发现 29、30）。
- 措辞改动先用已记录请求做 A/B 测量（同样的 state，只替换改动的那句话），再做真实运行（发现 28）。
- 在多样的输入上评判，真实调用，同样的种子，看整局层面的结果。
